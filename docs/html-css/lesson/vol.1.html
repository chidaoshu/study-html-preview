1.1.1

代表的なマークアップ言語

🟡 理解でOK

マークアップ言語（markup language）は、コンテンツにタグでマークを付け意味づけを行う形式言語です。

1.1.2

HTML のバージョン

🔴 試験重要

W3C（World Wide Web Consortium）が HTML 5.2 まで勧告し、以後はWHATWG（Web Hypertext Application Technology Working Group）が HTML Living Standard を管理しています。

年・月名称
1993年 6月HTML 1.0
1995年 11月HTML 2.0
1997年 1月HTML 3.2
1997年 12月HTML 4.0
1999年 12月HTML 4.01
2014年 10月HTML 5
2016年 11月HTML 5.1
2017年 12月HTML 5.2
2019年 6月HTML Living Standard
1.1.3

CSS

🔴 試験重要

CSS（Cascading Style Sheets）は Web ページのレイアウトと装飾を定義する言語で、コンテンツ（HTML）から見た目の情報を切り離します。

年・月名称

1998年 5月CSS2
2011年 6月CSS2.1

1.2.1

Web サイトが表示されるまでの流れ

🔴 試験重要

URL（Uniform Resource Locator）をアドレスバーに入力すると、クライアントが Web サーバーへリソースを要求し、受け取った HTML を解析して表示します。

1.2.2

URL の構成

🔴 試験重要

URL はスキーム（scheme）・ドメイン名（domain name）・ポート番号（port number）・ファイルパス（file path）・クエリ文字列（query string）・フラグメント（fragment）の 6 要素で構成されます。

1.2.3

IP アドレス

🟡 理解でOK

IP アドレス（Internet Protocol address）は通信先のコンピュータを識別する番号で、IPv4 は 32 ビットを 8 ビットごとにドットで区切り 10 進数で表します。

1.3.1

HTTP 通信の仕組み

🔴 試験重要

HTTP（HyperText Transfer Protocol）はクライアントとサーバーがテキスト・バイナリデータをやりとりするための通信プロトコルで、前の通信状態を考慮しないステートレス通信（stateless communication）です。

1.3.2

リクエストメッセージの構造

🔴 試験重要

リクエストメッセージはリクエストライン（request-line）・ヘッダー（header）・空白行（CR+LF）・メッセージボディ（message body）の 4 段で構成されます。

メソッドHTTP/1.0HTTP/1.1説明
HEAD○○URL で指定されたファイルのヘッダーのみを要求します。
GET○○指定した Web サーバー上のファイルの内容を要求します。
POST○○指定した Web サーバーにデータを送信します。送信データはメッセージボディに記述されます。
PUT○○Web サーバー上にファイルをアップロードします。
DELETE○○URL で指定したファイルを Web サーバー上から削除します。
TRACE×○HTTP の動作をトレースする際に使用します。
OPTIONS×○サポートされる通信オプションを調べる際に使用します。
CONNECT×○プロキシにトンネリングを要求する際に使用します。
LINK○×他の Web ページなどに関連付けます。
UNLINK○×関連付けを切り離します。
主なリクエストヘッダー説明
Hostリクエスト先の Web サーバー名を表します。
User-Agentクライアントが使用している Web ブラウザの名称やバージョンを表します。
Acceptクライアントが使用している Web ブラウザの受信可能なデータ形式を表します。
Accept-Languageクライアントが使用している Web ブラウザが優先する言語を表します。
Content-LengthPOST メソッドによるリクエストのみ適用され、POST のデータサイズを表します。
Connectionクライアントが持続性のある HTTP 接続を扱えるか否かを表します。
Originリクエスト元になります。
1.3.3

レスポンスメッセージの構造

🔴 試験重要

レスポンスメッセージはリクエストと同じ 4 段構成ですが、開始行がステータスライン（status-line）になり、HTTP バージョン・ステータスコード（status code）・リーズンフレーズ（reason phrase）を含みます。

範囲意味説明
100〜199お知らせリクエストが受け付けられて処理中であることを表します。
200〜299リクエスト成功リクエストに対して正常に処理が完了したことを表します。
300〜399移転通知リクエストが完了するには、追加の動作が必要であることを表します。
400〜499クライアントエラーリクエストに誤りがあることを表します。
500〜599サーバーエラーサーバーが処理に失敗したことを表します。
コードリーズンフレーズ説明
100Continueリクエストを継続して送信すべき状態であることを表します。
101Switching Protocolsプロトコルを変更しようとしている状態を表します。
200OKリクエストが正常に処理されたことを表します。
201CreatedPUT メソッドによって正常にファイルがアップロードされた事を表します。
300Multiple Choiceクライアントの選択を待っている状態を表します。
301Moved Permanentlyリクエストされたリソースに新しい URL が割り当てられています。新しい URL に自動的に転送されます。
302Foundリクエストされたリソースに一時的に新しい URL が割り当てられています。新しい URL に自動的に転送されます。
303See Otherリクエストに対する情報が他の URL に存在しています。自動的にその URL ページを表示させます。
304Not Modifiedリソースが更新されていないことを表します。この場合はキャッシュ済みのレスポンスを使用します。
307Temporary Redirect別の URL にリダイレクトが必要であることを表します。リクエストメソッドをそのまま用いて別の URL にアクセスします。
400Bad Requestリクエストの構文が間違えていることを表します。
401Unauthorized正しい識別情報のないクライアントが、パスワードで保護されたページにアクセスしようとしたことを表します。
403Forbiddenアクセスできないクライアントが、パスワードで保護されたページにアクセスしようとしたことを表します。
404Not Found指定したリソースが存在しないことを表します。
500Internal Server Error不特定のサーバーエラーを表します。

1.3.4

HTTP クッキー

🔴 試験重要

HTTP クッキー（HTTP Cookie）はサーバーがブラウザに送信する小さなデータで、次のリクエスト時に返送することでクライアントを識別し、セッション管理（session management）を実現します。

1.3.5

HTTPS 通信

🔴 試験重要

HTTPS（Hyper Text Transfer Protocol Secure）は HTTP にSSL（Secure Sockets Layer）による暗号化（encryption）を加えた通信プロトコルです。

1.3.6

認証

🟡 理解でOK

HTTP 通信で定義されているBasic 認証（Basic Authentication）とダイジェスト認証（Digest Authentication）は、パスワードで保護されたリソースへのアクセス制御を行います。

1.4.1

Web ブラウザ

🟡 理解でOK

Web ブラウザ（Web browser）は URL で指定したリソースをサーバーに要求し、受け取ったデータを表示するアプリケーションで、複数の構成要素が連携して動作します。

1.4.2

JavaScript

🟡 理解でOK

1995 年に Netscape Communications 社により開発されたブラウザ上で実行できるスクリプト言語（scripting language）で、プログラミング言語の Java とは無関係です。
