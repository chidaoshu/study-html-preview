HTML バージョン & CSS 分離/ HTML Versions & CSS Separation

標準化団体（W3C / WHATWG）の変遷と、CSSによる「コンテンツとレイアウト・装飾の分離」。

<!-- HTMLのみ：ブラウザデフォルト描画 -->
<h1>HTML&CSS 復習</h1>
<p>CSSを適用しない場合、文書の論理構造（h1, p）のみが素のスタイルで描画されます。</p>
<!-- HTML + CSS：コンテンツを変更せずレイアウト・装飾を変更 -->
<style>
  h1 { color: #d02020; border-bottom: 2px solid #111; padding-bottom: 4px; }
  p { background: #f5f5f3; padding: 10px; border-left: 4px solid #d02020; margin-top: 8px; }
</style>
<h1>HTML&CSS 復習</h1>
<p>CSSを分離定義することで、HTML構造を変えずに装飾やレイアウトを一括制御できます。</p>

SECTION 1.3.1 / 1.3.2

HTTP 通信 & リクエスト構造/ HTTP Protocol & Request Message

ステートレス通信（RFC 1945）の原則、リクエストメッセージ構造、HTTPメソッドおよびヘッダー。

<!-- リクエストライン: メソッド / パス / HTTPバージョン -->
GET /test/index.html HTTP/1.1
Host: localhost:8080
User-Agent: Mozilla/5.0 (Windows NT 10.0; ja)
Accept: text/html,application/xhtml+xml
Accept-Language: ja,en-us;q=0.7
Connection: keep-alive

<!-- ※GET通信ではメッセージボディは空 -->
<!-- POSTリクエスト: 送信データはボディに格納される -->
POST /test/index.html HTTP/1.1
Host: localhost:8080
User-Agent: Mozilla/5.0
Content-Type: application/x-www-form-urlencoded
Content-Length: 6
Connection: keep-alive

num=10
メソッド HTTP/1.0 HTTP/1.1 機能・説明
GET○○指定したサーバー上のファイル内容・データを要求・取得する。
POST○○サーバーにデータを送信する。送信データはメッセージボディに記述。
HEAD○○URLで指定されたファイルのヘッダー情報のみを要求する。
PUT○○Webサーバー上に指定ファイルをアップロードする。
DELETE○○URLで指定したファイルをWebサーバー上から削除する。
TRACE×○HTTP通信の動作をループバックトレースする。
OPTIONS×○サーバーがサポートする通信オプション（メソッド等）を調べる。
CONNECT×○プロキシに対してSSL等のトンネリング接続を要求する。
LINK○×リソースを他のWebページ等に関連付ける（1.1で廃止）。
UNLINK○×LINKによる関連付けを切り離す（1.1で廃止）。

※ステートレス通信（stateless communication）：過去の通信状態を維持せず、同一リクエストに対して常に同一レスポンスを返す性質。

ヘッダー名概要と説明
Hostリクエスト先の Web サーバー名（およびポート番号）を表す。
User-Agentクライアントが使用している Web ブラウザの名称・バージョン・OS情報を表す。
Acceptクライアントブラウザが受信可能なデータ形式（MIMEタイプ）を表す。
Accept-Languageクライアントブラウザが優先する言語（ja, en-us 等）を表す。
Content-LengthPOST メソッド等における送信データサイズ（バイト数）を表す。
Connection持続的な HTTP 接続（keep-alive）を扱うか否かを指定する。
Originリクエストの発信元スキーム・ドメイン・ポートを表す。

Content-Length: 48

ステータスコードの分類範囲
範囲分類名概要
100〜199お知らせ (Informational)リクエストが受け付けられ、処理が継続中であることを示す。
200〜299成功 (Success)リクエストが正常に理解され、受託・完了したことを示す。
300〜399移転通知 (Redirection)リクエスト完了のために追加の動作（リダイレクト等）が必要。
400〜499クライアントエラーリクエストの構文不正や認証不足などクライアント側の誤り。
500〜599サーバーエラーサーバーが正常なリクエストの処理に失敗したことを示す。
代表的なコード & リーズンフレーズ (Reason Phrase)
コードリーズンフレーズ詳細説明
100Continueリクエストの継続送信を促す状態。
101Switching Protocolsプロトコル切り替え要求に応じる状態。
200OKリクエスト正常処理完了。
201CreatedPUT等で新しいリソース作成が成功。
300Multiple Choice複数の選択肢が存在し、クライアント選択待ち。
301Moved Permanently恒久的なURL変更（自動リダイレクト）。
302Found一時的なURL変更（自動リダイレクト）。
303See Other他のURLにレスポンスが存在する。
304Not Modified未更新のためキャッシュ済データを使用。
307Temporary Redirectメソッドを変更せず一時リダイレクト。
400Bad Requestリクエストの構文エラー。
401Unauthorized認証（ユーザー名・パスワード）が必要。
403Forbiddenアクセス権限がないため禁止。
404Not Found指定リソースが存在しない。
500Internal Server Errorサーバー内部で不特定のエラー発生。

SECTION 1.3.4 / 1.3.5

HTTP Cookie & HTTPS セキュリティ/ Cookie Session & HTTPS Security

ステートレスなHTTP通信でセッション管理を実現するCookie機構と、SSL暗号化によるHTTPS通信。

<!-- サーバーからの初回レスポンス -->
HTTP/1.1 200 OK
Set-Cookie: session_id=XYZ123; Path=/
Content-Type: text/html

<html><body>ログイン成功</body></html>
<!-- ブラウザからの次回以降のリクエスト -->
GET /cart HTTP/1.1
Host: example.com
Cookie: session_id=XYZ123

<!-- サーバーはCookieからユーザーを識別（セッション管理） -->
項目HTTPHTTPS (HyperText Transfer Protocol Secure)
標準ポート80 番443 番
セキュリティなし（平文）SSL (Secure Sockets Layer) / TLS による暗号化
通信内容そのまま送信されるため盗聴可能通信路全体が暗号化されるため安全
